# Feature Specification: Общий Go linter и расширяемые проверки Service Kit — relay

**Статус:** черновик локального планирования; реализация `not-verified`.

Владелец: `services/relay`. Общая фича: [specs/002-shared-go-checks](https://github.com/endless-net/workspace/blob/0586e302ac17214698f95d95cc04d3a63ae4a470/specs/002-shared-go-checks/spec.md).
Создание этих файлов не разрешает обход локальных правил, изменение чужого
кода, публикацию, запуск агентов или чатов. Перед кодом уточнить локальный
план, выполнить analyze/Guard и разрешить зависимости общей функции.

## Разрешённый объём

- `C07` / `RB-relay`: Relay оба модуля и extensions. Контракт: N/A: dev/CI без изменения wire contracts. Owner autonomous product suites.

## Требования

- **FR-003**: Каждый репозиторий с собственным Go-кодом подключает общий линт для всех собственных модулей, тестов и применимых сборок локально и в CI.
- **FR-004**: Каждый Go-потребитель включает базовые проверки Service Kit; самостоятельный orchestration допустим лишь с документированным обоснованием и подключением той же общей основы без копии правил.
- **FR-005**: Потребитель может добавлять проверки; обязательные расширения участвуют в полном итоге и не могут удалить или ослабить базу.
- **FR-006**: Результат идентифицирует exact source commit, общий источник, инструменты, окружение, покрытие и каждый обязательный check; ошибки, пропуски, отмена, отсутствие результата и timeout не являются успехом.
- **FR-008**: Go baseline выполняется в Ubuntu 26.04 на GitHub-hosted раннерах публичных репозиториев и self-hosted раннерах приватных по STD-033; целевые ОС проверяются только для применимой платформенной логики; cross-build не считается runtime-тестом.
- **FR-009**: Миграция каждого владельца содержит локальные Spec Kit артефакты, модульный охват, способ подключения, свои сценарии, результаты и точный commit; отсутствующая реализация остаётся not-verified.
- **FR-010**: Общие технические проверки не подменяют domain tests, системную приёмку или production rollout; runtime contracts и полномочия остаются у принятых владельцев.

## Критерии и доказательства

### Measurable Outcomes

- **SC-001**: Все 18 зарегистрированных компонентов имеют объяснённый профиль; каждый собственный модуль включён в охват либо имеет конкретное обоснование неприменимости.
- **SC-002**: Для каждого Go-потребителя есть локальный и CI запуск общего набора на его exact commit; у заготовок отдельный статус без заявления о выполненной миграции.
- **SC-003**: Все обязательные проверки имеют отдельные результаты; каждый проверенный отрицательный случай блокирует успешный итог и выпуск.
- **SC-004**: На пилоте подтверждено расширение owner suite без копирования общей основы; его ошибка, пропуск, отмена и отсутствие результата блокируют итог.
- **SC-005**: Сводная приёмка закрывается только при наличии evidence всех реализованных Go-потребителей и явного списка незавершённых владельцев.

Общие критерии не считаются проверенными одним owner; evidence своего exact commit хранить здесь.
