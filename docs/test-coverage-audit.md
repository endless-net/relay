# Аудит функционального покрытия Relay тестами

Статус: завершён для реализованной функциональности Relay; проверено 2026-09-13
(Europe/Moscow). Область проверки: только этот репозиторий и продукт Relay.
Аудит не подтверждает корректность Coordinator интегратора или production-развёртывания.
Экспериментальные типы `relayapi/v1/extensions` — контракты с валидацией, а не
работающие функции передачи трафика. Версии протокола и Go-модуля не изменялись.

**Найдено, воспроизведено и исправлено 4 бага.** Описание каждого и проверяющие
его регрессионные тесты приведены в разделе «Найденные и исправленные баги».

## Критерии приёмки

- Для каждой реализованной функции есть положительный тест, соответствующие
  отрицательные и граничные сценарии, а при изменяемом состоянии — проверки
  восстановления и конкурентного доступа.
- Полные тесты сервиса используют настоящие бинарные файлы Relay и Relay
  Coordinator, PostgreSQL, mesh и изолированный SPIRE. Только внешний upstream
  заменён тестовым сервером с состоянием — stateful testserver.
- Быстрые тесты изолируют граничные случаи с управляемым временем и входными
  данными. Они не заменяют полные E2E и не подтверждают поведение Workload API.
- Корневая команда `go test ./...` не включает вложенный API-модуль и тесты
  PostgreSQL с тегом `integration`. CI проверяет их отдельно.
- Покрытие строк — диагностический показатель, а не доказательство полного
  функционального покрытия. Сгенерированный protobuf-код, запуск дочерних
  процессов и PostgreSQL нельзя оценивать только по проценту локальных unit-тестов.
- Новые тесты не должны молча пропускать проверки при отсутствии необходимых
  компонентов продуктового стенда в CI.
- Для завершения аудита необходимо закрыть все его пункты и успешно выполнить
  соответствующие проверки.

Полный перечень продуктовых сценариев и модель выполнения CI описаны в
[product-e2e.md](product-e2e.md). Каждая строка матрицы выше подтверждается
указанными регрессионными тестами и соответствующими продуктовыми группами,
а не только общим успешным статусом CI.

`TestProductMatrixIncludesEveryRegularScenario` сопоставляет фактические
объявления тестов Go с фильтрами CI. Запускаемый явно вручную длительный тест
`TestProductExtended` не учитывается как часть регулярных E2E.
Сгенерированные protobuf-геттеры и недостижимые ветви реализации кодека не
подменяют требования к поведению; произвольные цели покрытия строк для них не задаются.

Локальные ограниченные fuzz-прогоны: `FuzzStrictPublicFrame` проверил
1 173 981 вход, а `FuzzDiscoveryValidation` — 1 067 169 входов без ошибок.
Для каждого запрошено 5 секунд выполнения — около 6 секунд с завершением.
Это конечные прогоны, а не доказательство для всех возможных входных данных.

## Найденные и исправленные баги

**Всего: 4 бага; все 4 воспроизведены и исправлены.**

1. Входные данные upstream и результат чтения кэша доверия могли изменять
   внутреннее состояние кэша через общие срезы ключей и указатели времени.
   Проверка: `TestTrustCacheOwnsInputAndOutput`.
2. Обновление существующей записи в заполненном кэше без необходимости вытесняло
   другую запись. Проверка: `TestCacheReplacementDoesNotEvictUnrelatedEntry`.
3. Типизированный nil-ответ protobuf принимался за успешный пустой ответ.
   Проверки: `TestRejectTypedNilProtobufMessages`,
   `TestControlRejectsNilAndInvalidSessionResponses`.
4. Поверхностная копия данных доверия управляющего клиента раскрывала указатели
   на сроки действия ключей и позволяла изменять внутреннее состояние.
   Проверка: `TestCoordinatorStateRejectedAtomicallyAndTrustCopied`.

Все четыре регрессии воспроизведены до исправления; дополнительные
контрактные тесты добавлены после этого. Полная регулярная проверка ниже
выполнена на коде с исправлениями, а не на более раннем состоянии реализации.

## Длительная проверка восстановления и итоговая приёмка

[Расширенный CI 34719932178](https://github.com/endless-net/relay/actions/runs/34719932178)
выполнил регулярную продуктовую матрицу и отдельно выбранный `TestProductExtended`
на исходниках `867294c82ada49f47534334da69c411f727df4cc`.
JSON-артефакт фиксирует **1801.960 секунды, 317 завершённых циклов восстановления,
ноль ошибок и ноль пропущенных тестовых случаев**. Каждый цикл проверяет
двустороннюю связность, затем пересоздаёт Relay; каждый десятый цикл также
останавливает и запускает Relay Coordinator. Это конечная 30-минутная проверка
восстановления, а не неограниченная гарантия доступности или производительности.

Коммит слияния независимо проверен в
[CI ветки main 34721117770](https://github.com/endless-net/relay/actions/runs/34721117770).
Прогоны PR, ручного запуска и main проверяют одно и то же дерево исполняемых
исходников. Итоговое обновление результатов меняет только документацию и
не является новой проверкой работающего сервиса.

| Требование приёмки | Подтверждение и границы |

| Проверена полная интеграция сервиса Relay | Три экземпляра Relay, настоящий Relay Coordinator, PostgreSQL и mesh; 58 регулярных конечных тестовых случаев |

а не отсутствие всех возможных дефектов или покрытие будущих функций.
